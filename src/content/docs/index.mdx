**Create quickly. Verify seriously. Learn from every run.**

SpQE Lab is an independent applied-research project studying how an AI coding model can be placed inside a controlled software-production loop. The aim is not merely to generate code, but to build software, execute it, measure its observable behaviour, diagnose defects and support targeted repair.

<CardGrid>
  <Card title="Build">
    Turn an explicit software intent into a structured, multi-file executable prototype.
  </Card>

  <Card title="Qualify">
    Exercise the generated program through independent black-box controls and preserve the evidence.
  </Card>

  <Card title="Diagnose and repair">
    Localize contract or integration failures, apply narrow corrections and rerun qualification.
  </Card>
</CardGrid>

## What the current experiments show

Three executable comparisons against Kiro now document both strengths and limits. Kiro is currently more robust at first generation. SpQE nevertheless produces substantial domain behaviour, exposes failures through executable evidence and has demonstrated that localized defects can be closed without regenerating an entire program.

The dominant SpQE engineering problem is now concrete: **first-shot contract consistency between generated modules**.

This is a research result, not a hidden caveat. It identifies where model capability, orchestration and qualification can be measured separately.

## Why model teams may care

SpQE surrounds a coding model with explicit contracts, modular construction, observable qualification and evidence-guided repair. Replacing the model backend would make it possible to measure its effect on:

- first-shot inter-file consistency;
- executable contract compliance;
- inference time and cost;
- defect localization;
- repair trajectories.

A useful next experiment is therefore direct: connect a Mistral coding model to the same pipeline and rerun the executable benchmark series.
